# gmod-meshes-SF

Модульный Starfall-чип **Infantry Tool** (инструмент сапёра/строителя на `weapon_bugbait`).

Исходный чип был одним файлом на ~3600 строк. Здесь он разложен на 12 модулей,
которые главный файл подтягивает через `--@include` с GitHub, а затем грузит
обычным `require()`.

## Что внутри

| Файл | Что делает |
| --- | --- |
| `infantry_tool.lua` | главный чип: директива `--@name`, 12 `--@include` + `require()` |
| `src/config.lua` | настройки: дальности, тайминги, лимиты, материалы (`--@shared`) |
| `src/geom.lua` | примитивы (box/cyl/frustum/hex/bag…) и выпуклые оболочки (`--@shared`) |
| `src/shared.lua` | общие хелперы: тени, звук, углы, ранг предметов (`--@shared`) |
| `src/items.lua` | каталог предметов + определения мешей (68 предметов, 88 мешей) (`--@shared`) |
| `src/server/core.lua` | состояние, реестр объектов, размещение, взрывы, команды |
| `src/server/guns.lua` | станковые пулемёты, миномёты, наводка, снаряды |
| `src/server/sensors.lua` | мины, растяжки, сигнализации, радары, приманки |
| `src/client/core.lua` | клиентский стейт, think-цикл, шрифты, камера |
| `src/client/meshes.lua` | сборка визуала из `MDEFS` (корутина, 88/88 мешей) |
| `src/client/guns.lua` | клиентская часть орудий: прицел, дым, отдача |
| `src/client/build.lua` | меню постройки, призрак, сетка, тренчи, C4 |
| `src/client/hud.lua` | HUD, миникарта-радар, миномётный калькулятор |

`tools/` — только для разработки (в игру не грузится): `split.py` — генератор
модулей из исходника, `mock.lua` + `smoke.lua` + `smoke.py` — тесты на моке
Starfall, `apicheck.py` / `lint_names.py` — проверки API и имён.

## Установка

1. Убедитесь, что в StarfallEx разрешены URL-инклюды с GitHub. По умолчанию
   `raw.githubusercontent.com` уже в белом списке
   (`starfall_whitelist_default.lua`), но на сервере с кастомным списком может
   понадобиться строка в `garrysmod/data/sf_url_whitelist.txt`:

   ```
   simple [[raw.githubusercontent.com]]
   ```

   После правки — `sf_url_whitelist_reload` / перезаход.

2. В игре откройте Starfall → *New script* и вставьте содержимое
   **`infantry_tool.lua`** (только его, остальное подтянется само).

   Либо загрузите файл в `data/starfall/` — главный скрипт один, модули лежат
   в репозитории.

3. Чип `--@shared`: серверная половина компилируется на сервере, клиентская —
   на клиенте. Клиентские модули (`build`, `hud`) грузятся только у владельца.

4. Нажмите **Compile**. При первом запуске в консоль может прилететь
   `Could not fetch --@include link (...)` — это значит, что URL-инклюды
   запрещены правами Starfall или нет доступа к сети.

> Ветка модулей в `--@include` — `main`. Пока пулл-реквест не влит,
> ссылки будут отдавать 404; после мерджа чип работает как есть.

## Управление (кратко)

* ЛКМ — поставить выбранный предмет, ПКМ — меню/отмена.
* `C` — меню постройки, колесо — выбор предмета, `R` — поворот.
* Предметы категорий «мины» встают на землю и взводятся через 1.5 с.
* Таймер-заряд: ЛКМ поставить, ПКМ по нему — разминировать.
* Орудия: подойти к станку, `E` — сесть, ЛКМ — огонь, ПКМ — выйти.
* Cover-предметы (навес/маскировка) не создают новый объект — они
  переделывают уже стоящий тренч.

## Тесты

```bash
python3 tools/smoke.py        # mock-прогон сервера и клиента: 66 checks, 0 failed
python3 tools/apicheck.py /tmp/sf-src   # сверка вызовов с исходниками StarfallEx
```

`tools/split.py` — единственный источник `src/`: правки вносятся в шаблон
генератора, а не в сгенерированные файлы (регенерация перезапишет их).

## Оптимизации против исходного монолита

* `it_scan` больше не обходит все объекты 10 раз в секунду. Горящие
  запалы лежат в `S.fused` (свой маленький список), взведённые сенсоры — в
  `S.sensors`, который проверяется «каруселью»: не больше 24 проверок за тик,
  каждый сенсор — примерно раз в 0.1 с. Полный проход по `objs` (валидность и
  уборка мёртвых ссылок) — раз в секунду.
* Радар-пакет собирается из списка взведённых сенсоров, а не из всех объектов,
  и уходит 2 раза в секунду.
* Объекты хранятся в `objs`, у каждого — индекс меша; клиент не пересобирает
  визуал каждый кадр, а получает `it_reg`/`it_unreg` (позднее подключение
  синхронизируется по `ClientInitialized`).
* Сборка мешей на клиенте — одна корутина на объект, вместо блокирующего
  построения в основном потоке.
